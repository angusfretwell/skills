# Feature walkthrough

Lead with what the feature does; descend toward how it's built only at the end, if at all.

A section per point:

1. **What it is** — one paragraph: who the feature is for and the job it does.
2. **The journey** — captures in sequence, one per step of the flow, each captioned with what the user just did and what changed on screen.
3. **How it flows** — one journey or state diagram naming the real screens and states the captures showed.
4. **Where it lives** — short prose mapping the journey to the code: the entry points, linked as file references.
